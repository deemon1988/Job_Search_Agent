# База знаний кандидата для AI-агента по поиску работы

> Версия: 1.0  
> Дата подготовки: 2026-10-10  
> Назначение: источник подтверждённых сведений о кандидате для поиска вакансий, адаптации резюме, планирования обучения и подготовки портфолио.

## 1. Как использовать этот документ

Используй этот файл как основную базу знаний о кандидате. Отделяй подтверждённые сведения от предположений. Не выдумывай опыт, уровень владения технологиями, коммерческие результаты, сертификаты или завершённые курсы.

Если сведения противоречат друг другу или устарели, не делай вид, что противоречия нет: пометь поле как требующее уточнения и задай кандидату один конкретный вопрос, если без ответа нельзя двигаться дальше.

## 2. Цель поиска

- **Основная цель:** получить первую подходящую удалённую работу в IT.
- **Приоритет:** реальные вакансии с понятными требованиями, на которые можно откликнуться сейчас или после короткой целевой подготовки.
- **Желаемый формат:** полностью удалённая работа.
- **География поиска:** вакансии по России и другие вакансии, где работодатель явно разрешает работать из России.
- **Ориентир по доходу:** 40 000–60 000 рублей в месяц. Это ориентир, а не безусловное требование; сопоставляй его с реальными условиями вакансии.
- **Доступное время на поиск и подготовку:** примерно 3–4 часа в день.
- **Основной подход:** сочетать отклики с практическим обучением и созданием релевантного портфолио, не откладывая все отклики до завершения большого курса.

## 3. Образование и стартовая позиция

- **Образование:** среднее профессиональное образование по направлению «Специалист по информационным системам».
- **Опыт коммерческой работы в IT:** не подтверждён доступными сведениями. Не утверждать, что его нет, пока кандидат это не подтвердит; для резюме не придумывать коммерческий стаж.
- **Целевая стартовая позиция:** стажёр / Junior / начинающий технический специалист.
- **Место проживания:** Сосновый Бор, Ленинградская область, Россия. Использовать только для оценки географических ограничений вакансий; искать удалённые предложения по всей доступной географии, а не только в городе проживания.

## 4. Подтверждённые навыки и опыт

По сведениям кандидата, он создавал и публиковал проекты с помощью AI-инструментов, подключал базы данных и API. Уровень самостоятельности по отдельным технологиям следует проверять практическими заданиями, а не предполагать.

### Упоминавшиеся технологии и области

В материалах кандидата ранее перечислялись:

- Python, в том числе Django;
- Node.js;
- HTML и JavaScript;
- Java на базовом уровне;
- SQL;
- проектирование информационных систем;
- эксплуатация баз данных;
- чат-боты и AI-агенты;
- нейросети и AI-инструменты разработки;
- подход, известный как vibe coding;
- разработка на Tilda;
- интеграция с базами данных и API.

**Важно:** список отражает технологии и области, которые кандидат упоминал, но не подтверждает одинаково высокий или профессиональный уровень владения каждой из них. Для конкретной вакансии оценивай навыки как «подтверждены практикой», «нужно освежить», «частично знаком» или «не подтверждено».

### Практический профиль

Кандидат:
- использует AI-инструменты при создании программных продуктов;
- имеет опыт публикации проектов;
- подключал базы данных и API;
- готов создавать новые продукты;
- готов тестировать, анализировать и исправлять существующие продукты;
- способен изучать технические материалы на английском языке с помощью переводчика.

Не делай вывод, что кандидат умеет самостоятельно проектировать и поддерживать production-системы, пока это не подтверждено.

## 5. Приоритетные направления поиска

Рассматривай несколько направлений параллельно. Ранжирование ниже — исходная стратегия, её можно менять на основании реальных вакансий и результатов откликов.

### A. AI Automation / интеграции / AI-агенты

Искать роли, связанные с:
- n8n и автоматизацией процессов;
- интеграцией сервисов через API и вебхуки;
- AI-ассистентами и чат-ботами;
- подключением LLM API;
- обработкой данных;
- интеграцией с SQL-базами данных;
- low-code автоматизацией.

Возможные названия вакансий: AI Automation Specialist, специалист по автоматизации, интегратор API, разработчик AI-агентов, специалист по интеграциям.

### B. Junior Backend / начинающий разработчик

Искать роли, связанные с:
- Python или Node.js;
- backend и API;
- SQL и базами данных;
- исправлением ошибок и доработкой приложений;
- разработкой небольших веб-сервисов;
- тестированием и документированием кода.

Не ограничиваться одной технологией, если обязанности и уровень соответствуют возможностям кандидата.

### C. Junior QA / ручное тестирование

Искать роли, связанные с:
- тестированием веб-приложений;
- проверкой API;
- чек-листами и тест-кейсами;
- баг-репортами;
- регрессионным тестированием;
- анализом требований;
- постепенным освоением автоматизации тестирования.

Это допустимое самостоятельное направление, а не только запасной вариант.

### D. Технические low-code/no-code-роли

Рассматривать:
- интеграции CRM и внешних сервисов;
- автоматизацию бизнес-процессов;
- разработку на low-code-платформах;
- техническую работу с CMS;
- создание и сопровождение небольших веб-приложений.

Исключать вакансии, где под технической ролью фактически подразумеваются продажи, постоянные звонки или офисная поддержка.

## 6. Жёсткие ограничения

Не рекомендовать вакансии, если подтверждено, что они требуют:

- работы в офисе или гибридного присутствия;
- регулярных поездок в офис или к заказчикам;
- проживания в другом городе без возможности полностью удалённой работы;
- постоянной телефонной линии или работы в колл-центре;
- холодных звонков как основной обязанности;
- монтажа сетей, прокладки кабелей или установки оборудования на объектах;
- проживания/нахождения в стране, где кандидат не может легально работать, если это обязательное условие.

Если формат работы не указан, помечать его как **не подтверждён** и не считать вакансию подходящей до проверки. Техническую поддержку не исключать автоматически: анализировать реальные обязанности.

## 7. Резюме и профессиональное позиционирование

Ранее использовавшийся вариант целевой позиции:

**«Специалист по информационным системам / Младший разработчик (Junior Developer)».**

Для каждой вакансии адаптировать название и содержание резюме. Не использовать одно и то же позиционирование для AI Automation, Backend и QA без корректировки.

Рекомендуемые принципы:
- выделять реальные проекты и технические задачи;
- показывать опыт интеграции API и баз данных, если он релевантен;
- описывать, что именно сделал кандидат, какие инструменты использовал и как проверял результат;
- не выдавать учебные или личные проекты за коммерческий опыт;
- не приписывать экспертный уровень перечисленным технологиям;
- упоминать AI-инструменты как рабочий инструмент, но подкреплять это пониманием архитектуры, тестированием и отладкой.

## 8. Принципы оценки технических навыков

AI-инструменты могут ускорять разработку, но для работы важно уметь разбираться в полученном результате.

Проверяй и развивай способность кандидата:
- запускать проект и следовать инструкции;
- понимать назначение основных компонентов;
- объяснять движение данных между интерфейсом, API и базой данных;
- читать сообщения об ошибках;
- воспроизводить проблему;
- искать причину и проверять исправление;
- проверять API и SQL-запросы;
- писать или использовать тесты;
- работать с Git и документацией, если это требуется вакансией;
- хранить ключи и секреты безопасно;
- объяснять, где использовался AI и какие решения кандидат проверил сам.

Не требуй от кандидата обязательно писать весь код вручную или помнить синтаксис без подсказок. Оценивай способность безопасно решать задачу и объяснять решение.

## 9. Английский язык и обучение

- Подтверждённый рабочий подход: чтение технической документации на английском с помощью переводчика.
- Уровень английского по формальной шкале CEFR не подтверждён.
- Не указывать уровень B1/B2/C1 без отдельной оценки.
- Если вакансия требует устного английского, выяснять конкретный уровень и частоту коммуникации.
- Предпочитать обучение с практическими заданиями и бесплатные/недорогие материалы.
- Не считать просмотр курса доказательством навыка: требовать практический результат.

## 10. Рекомендуемая стратегия поиска

1. Искать удалённые вакансии по всей доступной географии, не ограничиваясь Сосновым Бором.
2. Проверять работодателя, актуальность, географию найма и фактические обязанности.
3. Сначала откликаться на вакансии, где совпадает значительная часть требований.
4. Параллельно закрывать небольшие пробелы в навыках.
5. Создавать проекты под требования реальных вакансий, а не ради количества проектов.
6. Отслеживать результаты откликов и корректировать стратегию.
7. Не проходить длительное обучение, если можно начать откликаться и учиться параллельно.

## 11. Возможный базовый проект для портфолио

Если соответствует целевой вакансии, рассмотреть проект **«AI-помощник для обработки заявок»**.

Возможные компоненты:
- форма или webhook для получения заявки;
- n8n или небольшой backend;
- LLM API для классификации/суммаризации;
- PostgreSQL или Supabase для хранения данных;
- валидация входящих данных;
- обработка ошибок и логирование;
- защита API-ключей;
- README с инструкцией запуска;
- тестовые сценарии и демонстрация.

Не считать этот проект обязательным для всех направлений. Для QA лучше подготовить набор тестов и баг-репортов; для Backend — API с базой данных; для low-code — законченную автоматизацию процесса.

## 12. Что пока требует уточнения

Не выдумывать ответы на следующие вопросы; уточнять их только тогда, когда они действительно нужны для решения задачи:

- точный уровень владения Python/Django, Node.js, JavaScript, SQL и Git;
- ссылки на опубликованные проекты и репозитории;
- наличие GitHub/GitLab и качество README;
- есть ли опыт командной работы или коммерческие проекты;
- готовность работать по часовому поясу работодателя;
- возможность оформления по трудовому договору, ГПХ или как самозанятый;
- минимально допустимая зарплата и возможность рассматривать предложения ниже ориентира;
- текущая версия резюме и контактные данные, которые кандидат хочет использовать;
- какие курсы уже пройдены;
- есть ли ограничения по графику, испытательному сроку или типу занятости.

## 13. Правила для AI-агента

- Используй этот документ как источник сведений о кандидате, а не как повод придумывать детали.
- Для каждой вакансии указывай прямую ссылку и дату проверки.
- Отделяй подтверждённые факты от выводов и предположений.
- Не выдавай старые вакансии за актуальные.
- Не отправляй отклики от имени кандидата без разрешения и доступного инструмента.
- Не раскрывай личные данные без необходимости.
- Не рекомендуй оплату за гарантированное трудоустройство.
- Не считай навык подтверждённым только по наличию технологии в списке.
- Каждый карьерный трек должен приводить к конкретным действиям и проверяемым результатам.
- Если подходящих вакансий мало, расширяй названия ролей, но не нарушай жёсткие ограничения.
